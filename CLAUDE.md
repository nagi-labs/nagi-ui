# Nagi UI contributor instructions

Read `CHARTER.md` before changing public behavior or component structure.
Preserve the native-first, visible-DOM, package-first/own-on-demand boundaries.

Use `vp` for all Node and package workflows. Run the relevant lint, unit,
integration, type, and browser checks before finishing. Blueprints must conform
to Nagi CSS, and package use and source ownership must share the same canonical
SFC.
